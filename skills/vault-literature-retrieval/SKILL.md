# vault-literature-retrieval：精读笔记库检索应答

工作区为 Research Vault（或用户明示基于笔记库回答）时，把用户输入当作检索请求处理。

## 回答流程

### 1. 读索引页（按序，缺失跳过，不报错）

1. `<vault_root>/文献索引.md`（全部精读笔记清单）
2. `<vault_root>/研究主题索引.md`
3. `<vault_root>/研究方法索引.md`
4. `<vault_root>/字段补全检查.md`

索引页只由索引任务维护；发现索引与笔记不一致时以笔记为准，并在回答中注明索引滞后。

### 2. 检索笔记

- 关键词检索 `<vault_root>/note/`（文件系统 grep 为主，Obsidian MCP 搜索可作辅助）
- 支持语义扩展：同义词、上下位概念由调用方自行判断，但**必须落到具体笔记文件**
- 命中后读取相关笔记全文，提取与该问题直接相关的部分

### 3. 只基于 Vault 证据回答

- 禁止把外部知识冒充 Vault 证据；Vault 支撑不了的，明确写 `Vault 中未找到足够依据`
- 引用时标注笔记文件名（如 `note/2024/张三-2024-xxx.md`），必要时引用原文并附页码

### 4. 回答结构（固定）

```
结论
支持文献
差异/争议
对我研究的启发
```

四段均可空，但顺序不变。`对我研究的启发` 段默认克制，仅当问题与研究方向相关时展开。

### 5. 证据不足 → 补读闭环（本技能的核心增量）

当问题重要且 Vault 证据不足以支撑时：

1. 明确告知用户证据缺口在哪（缺主题/缺方法/缺结论）
2. 经 Zotero MCP 搜索相关文献（调 lit-data-fetcher + lit-note-writer 生成补读笔记）
3. 回填后更新索引页，再基于新证据回答
4. 补读前先询问用户是否继续（涉及耗时与 token），用户确认后才执行

## 边界

- 本技能只回答"笔记里有什么"，不回答"笔记里没有但我知道的"
- 主观判断（`relevance`、`我的判断`）与论文结论区分呈现，不混为一谈
- 不修改笔记内容（补读生成新笔记除外）
